## Repository Structure

- `Frontend/` – User interface and frontend source code
- `Backend/` – Server-side code and application logic
- `Diagrams/` – UML diagrams, ERD, and system diagrams
- `Documentation/` – Project documentation

## Branching Convention

- `main` – Stable and approved project code
- `develop` – Integration branch for ongoing development
- `feature/feature-name` – Branch for a specific feature
- `fix/issue-name` – Branch for bug fixes
- `docs/topic-name` – Branch for documentation updates

All feature branches should be reviewed before merging into `develop`.

## Commit Message Convention

Use the following format:

`type: short description`

Examples:

- `feat: add login page`
- `fix: resolve form validation issue`
- `docs: update UML diagrams`
- `style: improve dashboard layout`
- `test: add registration test cases`
- `chore: organize repository folders`

## Team Collaboration Rules

1. Every member must use their own GitHub account.
2. Members must work on their assigned branches.
3. Changes should be committed with descriptive messages.
4. Pull requests should be reviewed before merging.
5. Do not commit passwords, API keys, or confidential information.
6. The Project Manager monitors repository progress and task completion.
